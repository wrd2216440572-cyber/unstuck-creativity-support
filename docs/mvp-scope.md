# Unstuck 平台 MVP 范围说明

## 文档定位

本文档用于确定 Unstuck 平台首版可交互原型的目标、页面范围、功能边界、模拟 AI 内容结构、未来真实 AI API 的数据预留，以及形成性评价可收集的数据。

MVP 服务于论文《面向小学高年级开放性学习任务的 AI 创造力支架设计原则研究》，优先面向小学五、六年级学生的开放性写作、表达和创造任务。它不是通用聊天机器人，也不是作业生成工具。

当前仍处于开发前的范围确认阶段。本文档不代表已经创建前端工程、安装依赖、接入后端或接入真实 AI API。只有在用户明确确认开发方案后，才进入代码实现。

## 一、MVP 目标

### 1.1 核心验证目标

MVP 只验证一个核心命题：

> 结构化、非代答的 AI 创造力支架，能否帮助小学高年级学生在开放性任务中识别卡点、恢复自己的思考，并形成一个可以立即开始的下一步行动。

首版不以“生成更好的答案”为成功标准，而以学生是否经历了以下变化作为观察重点：

1. 能否说清自己卡在哪里；
2. 能否把模糊任务缩小为当前要解决的小问题；
3. 能否产生、补充或改变自己的想法；
4. 能否从不同方向中作出选择并说明理由；
5. 能否把内部想法外化为关键词、结构或简短表达；
6. 能否形成一个五至十五分钟内可开始的最小行动；
7. 能否总结哪种策略有帮助，以及下次可以先尝试什么。

### 1.2 MVP 的研究作用

MVP 是设计原则的操作化载体，主要用于：

- 检查五类卡住情境是否容易被学生理解；
- 检查八阶段支架模型能否形成连贯但可跳转的流程；
- 检查 AI 输出规则能否维持“学生先产出、AI 不代答”；
- 检查单步交互和分级提示是否符合小学高年级学生的理解负担；
- 检查视角转换、表达外化和最小行动等环节是否需要调整；
- 为教师或专家审查、认知走查和后期小规模试用提供材料；
- 记录设计原则如何转化为功能，并为论文第五章积累设计决策。

### 1.3 MVP 的完成标准

MVP 达到以下条件即可视为完成首版，而不要求成为完整产品：

- 用户能够从首页完成一次完整或按需跳转的支架流程；
- 五类卡住情境均有至少一条可执行路径；
- P0 方法形成“澄清—生成—选择—行动—反思”的基本闭环；
- 所有模拟 AI 输出均来自预设规则和内容数据；
- 每个阶段都要求学生输入、选择、修改或确认；
- 不出现可直接提交的完整作文、演讲稿或创意方案；
- 用户可以返回、跳过、换方法、暂停或结束；
- 能够在不收集身份信息的前提下记录必要的本地评价数据；
- 页面结构能够支持后续接入受约束的真实 AI API，而不需要改变核心研究流程。

## 二、MVP 不做什么

### 2.1 不做通用 AI 聊天

- 不提供自由聊天作为默认入口；
- 不允许系统脱离卡住情境和支架阶段随意回答；
- 不围绕聊天轮次组织产品；
- 不把“和 AI 多聊几轮”当作支架成功。

### 2.2 不直接完成学生任务

- 不生成完整作文、演讲稿、作品说明或可提交方案；
- 不替学生确定最终观点、情节、创意方向或表达；
- 不连续输出多个成熟方案供学生照抄；
- 不提供“一键成稿”“帮我全部写完”等功能；
- 不把 AI 输出的流畅度当作学生创造力。

### 2.3 不验证长期创造力提升

- 不进行长期创造力测评；
- 不声称一次或少量使用能够提高稳定人格特质；
- 不把完成任务、使用满意或行动更快直接等同于创造力提升；
- 不在首版进行大规模随机对照实验。

### 2.4 不覆盖所有用户和任务

- 不验证平台适用于所有年龄；
- 不覆盖封闭式练习题、标准答案问答和复杂学科辅导；
- 不覆盖情绪危机、心理治疗或专业诊断；
- 不承诺五类卡住情境构成完整分类体系；
- 不把面向所有人的长期愿景纳入首版评价结论。

### 2.5 不实现完整产品基础设施

- 不实现正式账号、登录、社交或排行榜；
- 不实现教师后台、班级管理或家校系统；
- 不实现云端同步、跨设备历史记录或消息通知；
- 不实现支付、订阅或商业化功能；
- 不接入后端数据库；
- 不接入真实 AI API；
- 不保存姓名、学校、联系方式等不必要信息。

### 2.6 不把扩展方法设为首版强制功能

首版优先实现卡住识别、问题重构、发散生成、聚合筛选、表达外化、任务拆解、最小行动和反思反馈。

SCAMPER、类比、角色转换可作为受控的视角转换选项。随机刺激、强制联结、反向假设和人为限制属于待验证方法，不应默认出现，也不应成为完成流程的必要条件。

## 三、首版页面结构

### 3.1 页面总览

首版采用八个核心页面：

| 页面编号 | 页面名称 | 对应过程阶段 | 页面目标 |
|---|---|---|---|
| P01 | 首页与使用边界 | 流程入口 | 让学生理解平台用途、非代答边界与开始方式 |
| P02 | 卡住情境选择页 | 卡住识别 | 帮助学生选择或描述当前主要卡点 |
| P03 | 任务澄清页 | 任务澄清 | 把任务缩小为当前要解决的小问题 |
| P04 | 想法生成页 | 发散生成 | 支持学生产生或补充多个不同方向 |
| P05 | 换个角度页 | 视角转换 | 按需使用一个可解释、可退出的创造力方法 |
| P06 | 想法整理页 | 聚合筛选与表达外化 | 比较、选择、改进并外化学生自己的想法 |
| P07 | 最小行动页 | 最小行动 | 将选定方向转为可立即开始的小步骤 |
| P08 | 反思与结束页 | 反思迁移 | 记录变化、有效策略与下次自主尝试 |

### 3.2 页面跳转原则

八个页面对应完整过程，但实际使用不要求机械走完全部页面。

- “不知道从哪里开始”通常进入 P03，再根据需要前往 P04 或直接进入 P07；
- “完全没有想法”通常从 P03 进入 P04；
- “只有一个普通想法”可从 P03 或 P04 进入 P05；
- “有想法但不会表达”可从 P03 直接进入 P06；
- “知道要做但无法行动”可从 P03 直接进入 P07；
- P05 是按需启用页面，不能成为所有路径的强制步骤；
- P06 发现没有可用方向时，可以返回 P04 或 P05；
- 任何支架页都应允许暂停、换方法或结束；
- 完成 P07 后进入 P08，形成反思闭环。

## 四、每个页面的功能说明与设计原则

本节使用 `docs/design-principles-draft.md` 中的八条原则：

- **DP1：** 以过程性卡点识别替代能力诊断；
- **DP2：** 坚持学生先产出与 AI 非代答；
- **DP3：** 采用年龄适切的单步认知动作与分级提示；
- **DP4：** 分离发散生成与聚合评价；
- **DP5：** 以可选择、可解释的视角转换拓展思路；
- **DP6：** 支持多表征表达与渐进外化；
- **DP7：** 以学生确认的最小行动形成支架闭环；
- **DP8：** 通过反思迁移、支架撤除与儿童安全维持长期自主性。

### 4.1 P01 首页与使用边界

#### 页面目标

让学生在进入流程前理解平台“帮助思考、不替你完成”的定位，并知道输入内容的安全边界。

#### 核心功能

- 一句话定位：“不是替你写答案，而是陪你找到继续思考的下一步”；
- 展示适用任务：开放性写作、表达和创造任务；
- 展示三个基本承诺：由学生产生内容、可以跳过或退出、不要输入个人敏感信息；
- 显示 AI 可能出错和必要时寻求教师或家长帮助的说明；
- “开始脱卡”主入口；
- 可选的“这不适合什么任务”说明。

#### 页面输入与输出

- 输入：是否开始；
- 输出：创建一次匿名本地会话，进入 P02；
- 不要求输入姓名、学校、班级或联系方式。

#### 对应设计原则

- DP2 学生先产出与 AI 非代答；
- DP3 年龄适切的单步认知动作；
- DP8 反思迁移、支架撤除与儿童安全。

### 4.2 P02 卡住情境选择页

#### 页面目标

帮助学生以非诊断方式识别当前最主要的过程卡点。

#### 核心功能

- 五类卡住情境卡：
  - 不知道从哪里开始；
  - 完全没有想法；
  - 只有一个普通想法；
  - 有想法但不会表达；
  - 知道要做但无法行动；
- 每张卡只提供一至两个儿童化表现示例；
- “我不确定”入口，通过两个以内的辅助问题帮助选择；
- 允许填写一句自己的描述；
- 允许返回、重新选择或跳过；
- 选择后显示暂定确认：“听起来你现在可能卡在……，之后可以更改。”

#### 页面输入与输出

- 输入：主要卡点、可选自由描述、使用前卡住程度；
- 输出：暂定 `stuck_type`、初始过程入口和首选支架方向；
- 卡点只作为流程匹配依据，不作为能力诊断。

#### 对应设计原则

- DP1 过程性卡点识别；
- DP3 年龄适切的单步认知动作；
- DP8 儿童安全与可退出。

### 4.3 P03 任务澄清页

#### 页面目标

以尽可能低的输入负担，确定学生正在做什么、已经做到哪里和当前最想推进的小问题。

#### 核心功能

- 三个核心输入：
  - 我正在做什么；
  - 我已经有了什么；
  - 我现在最想先解决什么；
- 可选输入：任务限制、已有材料或截止时间；
- 支持“已知—未知—限制”简化卡片；
- 模拟 AI 先复述，再提出一个澄清问题；
- 帮助学生把大任务改写成一个小问题；
- 由学生确认或修改当前小问题；
- 根据卡点决定下一页，不强制进入发散。

#### 页面输入与输出

- 输入：任务描述、当前进度、已有想法、限制条件；
- 输出：学生确认的 `focus_question`、任务类型和下一阶段；
- 模拟 AI 不生成完整解决方案。

#### 对应设计原则

- DP1 过程性卡点识别；
- DP2 学生先产出与 AI 非代答；
- DP3 单步动作与分级提示。

### 4.4 P04 想法生成页

#### 页面目标

帮助学生在暂缓评价的条件下，生成或补充多个有差异的候选方向。

#### 核心功能

- 默认提供三个空白想法槽位；
- 学生先填写至少一个想法；
- “再来一个不同方向”提示；
- 可按人物、地点、目的、材料、对象或形式提供一个类别提示；
- 支持“更大胆”和“更简单”两个方向变化；
- 发散阶段不显示评分、最佳答案和淘汰；
- 学生持续卡住时，才展示一个局部框架或不完整候选；
- 可直接进入 P06，也可按需进入 P05。

#### 页面输入与输出

- 输入：学生想法、想法类别、是否需要提示；
- 输出：若干 `idea_item`，并记录来源是学生原创、AI 提示后修改或框架填写；
- 不把想法数量直接解释为创造力水平。

#### 对应设计原则

- DP2 学生先产出与 AI 非代答；
- DP3 单步动作与分级提示；
- DP4 发散与聚合分离。

### 4.5 P05 换个角度页

#### 页面目标

在学生只有一个普通想法、思路固定或主动选择时，用一个可解释的方法拓展思路。

#### 核心功能

- 根据卡点只推荐一个首选方法；
- 首版允许的受控方法：
  - 角色或受众转换；
  - 一张儿童化 SCAMPER 操作卡；
  - 简单类比桥；
- 每次只展示一个视角或操作；
- 简要说明“为什么试这一招”；
- 要求学生说明新视角改变了什么；
- “没帮助，换一种”与“跳过”入口；
- 不默认使用随机刺激、强制联结或复杂反向假设。

#### 页面输入与输出

- 输入：选用的方法、学生对新视角的连接和新想法；
- 输出：`method_attempt`、变化说明和新增或修改后的想法；
- 方法匹配结果是可修正假设，不是确定处方。

#### 对应设计原则

- DP2 学生先产出与 AI 非代答；
- DP3 单步动作与分级提示；
- DP5 可选择、可解释的视角转换；
- DP8 允许退出和避免刻板印象。

### 4.6 P06 想法整理页

#### 页面目标

帮助学生比较、选择、组合和表达自己的想法，同时保持最终决定权。

#### 核心功能

- 以卡片形式展示学生已经产生的想法；
- 使用三个儿童化比较维度：
  - 有点不一样；
  - 符合任务；
  - 我愿意继续；
- 由学生选择一个方向，或合并两个方向；
- 提供“保留什么—改变什么—还要补什么”改进框架；
- 表达外化方式：
  - 关键词；
  - 一句话；
  - 内容排序；
  - 简单结构；
  - 图画或口述的文字说明；
- AI 只整理学生已有内容；
- 整理结果必须由学生确认“这是我的意思”。

#### 页面输入与输出

- 输入：选择结果、选择理由、保留与修改内容、表达形式；
- 输出：`selected_idea`、`selection_reason` 和 `externalized_outline`；
- 如果没有合适方向，可返回 P04 或 P05。

#### 对应设计原则

- DP2 学生先产出与 AI 非代答；
- DP4 发散与聚合分离；
- DP6 多表征表达与渐进外化。

### 4.7 P07 最小行动页

#### 页面目标

将学生选定的方向转化为一个可以立即开始的具体步骤。

#### 核心功能

- 显示学生自己选定的方向；
- 使用“动作＋对象＋时间或数量”模板；
- 提供五分钟和十五分钟两个缩小选项；
- 模拟 AI 只提出一个主要行动建议；
- 学生可以修改、进一步缩小或拒绝；
- 检查行动是否：
  - 具体；
  - 无需大量额外准备；
  - 与选定方向相关；
  - 可以立即开始；
- “我现在可以开始”确认；
- 可选记录“完成后回来看看”但不实现通知。

#### 页面输入与输出

- 输入：学生修改和确认的行动内容；
- 输出：`minimum_action`、预计时间和开始意愿；
- 不把行动确认解释为创造力提升。

#### 对应设计原则

- DP2 学生保留决定权；
- DP3 单步动作；
- DP7 学生确认的最小行动；
- DP8 自主性和安全。

### 4.8 P08 反思与结束页

#### 页面目标

让学生回顾本次变化，形成可迁移的策略认识，并安全结束会话。

#### 核心功能

- 使用后卡住程度自评；
- “我现在有没有新的方向”；
- “哪一步最有帮助”；
- “哪一步没有帮助或太难”；
- “我的下一步清楚吗”；
- “我愿意现在开始吗”；
- “下次遇到类似情况，我想先试什么”；
- 显示由学生填写的策略卡；
- 提供删除本次本地记录的选项；
- 再次提醒 AI 可能出错，必要时寻求教师或家长帮助；
- 结束会话或重新开始。

#### 页面输入与输出

- 输入：使用后反馈、策略总结和开放意见；
- 输出：`reflection_summary` 和匿名评价记录；
- 不由 AI 代写反思结论。

#### 对应设计原则

- DP2 学生自己总结；
- DP7 行动闭环；
- DP8 反思迁移、支架撤除与儿童安全。

## 六、Mock AI 输出的内容结构

### 6.1 Mock AI 的定位

首版 Mock AI 不是聊天模型，也不模拟无限生成能力。它由预设规则、固定内容模板和少量变量替换组成，用于验证：

- 情境到支架阶段的匹配；
- 单步提示是否清晰；
- 提示层级是否合理；
- 非代答边界是否能够落实；
- 学生是否愿意输入、选择、修改和确认；
- 页面之间的跳转是否连贯。

Mock AI 输出必须使用统一的结构化对象，以便未来在不改变页面逻辑的情况下替换为真实 AI API。

### 6.2 单次 Mock AI 输出结构

```json
{
  "outputId": "mock-output-001",
  "stage": "task_clarification",
  "stuckType": "dont_know_where_to_start",
  "methodId": "problem_reframing",
  "principleIds": ["DP1", "DP2", "DP3"],
```

### 6.3 Mock AI 字段说明

| 字段 | 含义 | MVP 要求 |
|---|---|---|
| `outputId` | 输出内容唯一标识 | 用于记录用户看到的具体版本 |
| `stage` | 所属八阶段 | 必填，不允许脱离阶段自由输出 |
| `stuckType` | 当前暂定卡点 | 可为空，但不得作为能力诊断 |
| `methodId` | 当前使用的方法 | 必填，如问题重构、发散、聚合 |
| `principleIds` | 对应设计原则 | 用于设计追溯和评价分析 |
| `supportLevel` | 提示层级 | 1 至 4，依次为开放、动作、框架、有限候选 |
| `purposeLabel` | 儿童可理解的方法目的 | 简短说明“为什么做这一步” |
| `acknowledgement` | 对学生输入的简短复述 | 不评价能力，不夸大理解 |
| `prompt` | 本轮唯一主要问题或动作 | 一次只推进一个认知动作 |
| `responseMode` | 学生回答方式 | 如短文本、单选、多项卡片、排序 |
| `options` | 有限选项 | 可选；数量少且不得构成完整答案 |
| `studentActionRequired` | 是否要求学生输入或选择 | 原则上为 `true` |
| `allowSkip` | 是否允许跳过 | 支持学生选择权 |
| `allowMethodSwitch` | 是否允许换方法 | 视阶段启用 |
| `nextStageOnSubmit` | 提交后默认阶段 | 支持规则跳转 |
| `fallbackOutputId` | 持续卡住时的下一层提示 | 不自动连续展示 |
| `safetyNote` | 必要的安全提醒 | 平时为空，高风险或敏感内容时启用 |

### 6.4 Mock AI 内容类型

首版允许以下输出类型：

- **确认型：** 简短复述学生卡点并询问是否准确；
- **澄清型：** 询问目标、已有内容、限制或具体停点；
- **激发型：** 邀请学生再产生一个不同类别的方向；
- **方法型：** 说明一个方法，并要求学生完成一个操作；
- **比较型：** 提供少量评价维度，让学生自己选择；
- **整理型：** 重新排列学生已有内容，并要求确认；
- **行动型：** 将学生选定方向缩小为一个可修改的小步骤；
- **反思型：** 邀请学生总结有效策略；
- **安全型：** 停止当前支架并建议寻求可信成人帮助。

### 6.5 Mock AI 禁止输出

- 完整可提交作品；
- 超过本阶段所需的多步方案；
- 多个成熟创意成品；
- 对学生创造力、能力或人格的评价；
- 确定性的心理或学习诊断；
- 要求输入姓名、学校、联系方式等身份信息；
- 无法解释来源的评价分数；
- 在高风险情境中继续提供普通创造力提示；
- 将“你完成得更快”表述为“你的创造力提高了”。

## 七、未来接入真实 AI API 时需要预留的数据字段

### 7.1 预留原则

真实 AI API 只能替换 Mock AI 的内容生成层，不能改变以下核心约束：

- 页面仍按受约束流程组织；
- AI 请求必须带有阶段、方法和输出边界；
- 学生仍需先输入、选择、修改或确认；
- 输出必须通过结构验证、安全检查和长度限制；
- 不允许真实模型退化为自由聊天或作业代写；
- 儿童数据继续遵循最小化原则。

### 7.2 会话与任务字段

| 字段 | 类型示例 | 用途 | 隐私要求 |
|---|---|---|---|
| `sessionId` | 随机字符串 | 关联一次支架流程 | 不与真实身份绑定 |
| `sessionVersion` | 字符串 | 标记流程与规则版本 | 用于研究追溯 |
| `startedAt` | 时间戳 | 计算流程时长 | 可降低时间精度 |
| `locale` | `zh-CN` | 控制语言 | 不记录位置 |
| `ageBand` | `upper_primary` | 控制年龄适切输出 | 不记录出生日期 |
| `taskType` | `writing` / `expression` / `creation` | 选择任务模板 | 只记录粗分类 |
| `taskDescription` | 短文本 | 支架当前任务 | 发送前进行敏感信息提醒 |
| `currentProgress` | 短文本 | 了解学生已有内容 | 限制长度 |
| `taskConstraints` | 字符串数组 | 记录材料、时间等限制 | 不收集身份信息 |
| `focusQuestion` | 短文本 | 当前要推进的小问题 | 由学生确认 |

### 7.3 支架状态字段

| 字段 | 类型示例 | 用途 |
|---|---|---|
| `stuckType` | 枚举 | 当前暂定卡点 |
| `stuckDescription` | 短文本 | 学生自己的卡点描述 |
| `currentStage` | 枚举 | 八阶段中的当前位置 |
| `methodId` | 枚举 | 当前创造力或支架方法 |
| `methodVersion` | 字符串 | 追踪方法脚本版本 |
| `supportLevel` | 1 至 4 | 控制提示强度 |
| `previousMethods` | 数组 | 避免重复无效方法 |
| `methodHelpful` | `yes` / `no` / `unsure` | 支持换方法与后期分析 |
| `studentAttemptCount` | 整数 | 判断是否已给学生尝试空间 |
| `stageHistory` | 枚举数组 | 记录跳转、回退和跳过 |

### 7.4 学生过程产出字段

| 字段 | 类型示例 | 用途 | 边界 |
|---|---|---|---|
| `studentInputs` | 对象数组 | 保存各阶段学生输入 | 可只保存在本地或去标识化 |
| `ideaItems` | 对象数组 | 保存候选想法与版本 | 标记来源与修改关系 |
| `ideaSource` | `student` / `ai_prompted_student` / `ai_candidate_modified` | 区分贡献来源 | 不把 AI 候选记为学生原创 |
| `selectedIdeaId` | 字符串 | 记录学生最终选择 | 必须由学生确认 |
| `selectionReason` | 短文本 | 记录选择理由 | 不由 AI 代写 |
| `externalizedOutline` | 对象 | 保存关键词、排序或结构 | 不要求完整作品 |
| `minimumAction` | 对象 | 保存动作、对象、时限 | 由学生修改和确认 |
| `reflectionText` | 短文本 | 保存学生策略总结 | 可选择不保存原文 |

| 字段 | 用途 |

| `allowedMethodIds` | 限定当前可使用的方法 |
| `forbiddenBehaviors` | 明确禁止代写、诊断和索取隐私 |

| 字段 | 用途 |

| `options` | 有限候选或操作选项 |
| `studentActionRequired` | 防止模型连续自说自话 |
| `nextStageSuggestion` | 仅作为规则系统参考 |
| `safetyClassification` | 标记安全风险类别 |

| `dependencyRiskSignal` | 标记反复要求 AI 直接决定或生成 |

### 7.8 不应预留或收集的字段

除非后续研究伦理方案明确要求并获得批准，首版及未来 API 不应收集：

- 学生真实姓名；
- 具体出生日期；
- 学校、班级、学号；
- 家庭住址；
- 电话、邮箱和社交账号；
- 精确位置；
- 与支架任务无关的健康、家庭或身份信息；
- 用于给儿童建立长期画像的隐性行为标签；
- “创造力高低”“能力等级”等未经验证的标签。

## 八、形成性评价可收集的数据

### 8.1 数据收集目的

评价数据只用于检查设计原则、流程清晰性、非代答边界、认知负担和潜在风险。首版不以这些数据证明长期创造力提升。

在真实儿童参与前，必须确认招募方式、监护人知情同意、儿童同意、学校或机构伦理要求、数据保存范围和退出机制。

### 8.2 使用前数据

| 数据 | 建议形式 | 作用 |
|---|---|---|
| 任务类型 | 写作、表达、创造 | 判断不同任务路径 |
| 暂定卡住类型 | 五类卡点＋不确定 | 检查情境分类可理解性 |
| 学生自己的卡点描述 | 一句话，可选 | 检查预设分类是否覆盖真实表达 |
| 使用前卡住程度 | 1 至 5 级儿童化量表 | 描述使用前状态 |
| 已有想法数量 | 无、1 个、2 个及以上 | 判断起始状态 |
| 当前下一步清晰度 | 1 至 5 级 | 与使用后比较 |
| 当前行动意愿 | 1 至 5 级 | 与使用后比较 |

### 8.3 过程数据

| 数据 | 作用 |
|---|---|
| 实际经过的阶段 | 检查路径是否需要跳转或回退 |
| 每个页面停留时间 | 发现理解困难或负担过高的页面 |
| 返回、跳过和退出次数 | 检查流程阻塞与选择权 |
| 使用的支架方法 | 比较不同卡点下的方法使用情况 |
| 提示最高层级 | 判断开放提示是否足够、何时需要结构化支持 |
| 每阶段学生尝试次数 | 检查是否真正做到学生先产出 |
| “这没有帮助”次数 | 识别无效方法或不适配路径 |
| 换方法次数与顺序 | 检查匹配机制 |
| 候选想法数量 | 描述过程，不单独作为创造力指标 |
| 想法类别差异 | 初步观察方向多样性 |
| 想法来源标记 | 区分学生原创、AI 提示后修改和 AI 候选修改 |
| 选择理由是否填写 | 检查学生是否参与聚合决策 |
| 表达外化方式 | 文字、关键词、排序、图画说明等 |
| 最小行动修改次数 | 检查 AI 建议是否过大或不合适 |
| 安全提醒、退出或求助触发 | 检查儿童安全机制 |

### 8.4 使用后数据

| 数据 | 建议形式 | 作用 |
|---|---|---|
| 使用后卡住程度 | 与使用前相同的 1 至 5 级量表 | 描述短期状态变化 |
| 是否产生新方向 | 是、否、不确定 | 检查支架是否帮助继续思考 |
| 下一步清晰度 | 1 至 5 级 | 检查最小行动效果 |
| 当前行动意愿 | 1 至 5 级 | 描述是否愿意开始 |
| 最有帮助的阶段 | 单选＋可选说明 | 定位有效功能 |
| 没有帮助或太难的阶段 | 单选＋可选说明 | 定位问题 |
| 提示是否像在代答 | 完全不像至非常像 | 检查非代答边界 |
| 提示是否容易理解 | 1 至 5 级 | 检查年龄适切性 |
| 步骤是否太多 | 太少、合适、太多 | 检查认知负担 |
| 是否保留选择权 | 是、部分、否 | 检查学生主体性 |
| 是否愿意再次使用同一方法 | 是、否、不确定 | 检查策略接受度 |
| 下次准备先尝试的策略 | 学生短文本 | 检查反思迁移 |
| 开放意见 | 可选短文本 | 收集未预设问题 |

### 8.5 教师或专家评价数据

如果后续进行教师访谈或专家审查，可收集：

- 五类卡住情境的清晰性与覆盖度；
- 情境与方法匹配是否合理；
- 各页面语言是否符合小学五、六年级；
- AI 输出是否保持非代答；
- 支架强度是否过高或过低；
- 发散与聚合是否清楚分离；
- 表达外化是否保留学生原意；
- 最小行动是否真正可执行；
- 是否存在错误、依赖、刻板印象、隐私或学术诚信风险；
- 哪些环节需要教师介入；
- 哪些数据不应收集；
- 对设计原则修改、合并或新增的建议。

### 8.6 评价数据的解释边界

- 卡住程度下降只能说明学生的短期主观体验变化；
- 想法数量增加不能单独证明创造力提升；
- 最小行动更清晰不能直接证明长期自主性；
- 学生喜欢平台不能证明支架有效；
- 小样本结果只能用于形成性改进；
- 不同任务之间的数据不能在未控制差异时直接比较；
- 儿童数据必须匿名化、最小化，并允许退出和删除；
- 评价结果应与过程记录、学生反馈和教师或专家意见交叉解释。

## 九、开发前确认清单

进入代码开发前，仍需由用户明确确认：

- 首个案例任务采用写作、表达还是创造任务；
- 八个页面是否全部进入首版，或是否合并 P04 至 P06；
- P05 首版启用哪些视角转换方法；
- Mock AI 内容使用何种案例脚本；
- 数据仅保存在浏览器本地，还是完全不持久化；
- 是否在首版加入语音、绘画等真实输入，还是只保留占位流程；
- 评价问卷是否进入 MVP，还是独立于平台实施；
- 后续开发的技术栈、组件范围和构建检查方式。

在以上事项确认前，不创建 React/Vite 项目、不安装依赖、不接入后端或真实 AI API。
