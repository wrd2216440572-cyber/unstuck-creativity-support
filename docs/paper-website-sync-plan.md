# 论文与网站同步推进计划

## 文档定位

本计划用于协调毕业论文与 Unstuck 网站的推进顺序。当前仍处于构思与文档整理阶段，本计划不代表已经确认最终论文题目、研究对象或技术方案，也不启动 React 项目、后端或真实 AI API。

当前暂定的同步逻辑是：

**论文提出理论依据与研究问题 → 网站把理论转化为可体验的支架流程 → 用户反馈为论文提供设计证据 → 论文分析结果再指导网站迭代。**

---

## 一、项目总目标

### 1. 网站为什么存在

学生面对写作、学习、表达或开放性任务时，常常不是完全缺少知识，而是暂时失去继续思考和行动的路径。普通搜索或通用 AI 问答工具容易直接给出答案，却可能跳过学生识别问题、发展想法和自主决策的过程。

Unstuck 网站希望成为一个“AI 创造力支架工具”，帮助学生：

1. 识别自己属于哪一种“卡住”状态；
2. 理解当前阻碍来自想法不足、任务模糊、表达困难、完美主义还是行动困难；
3. 使用与卡住情境匹配的创造力方法继续思考；
4. 形成多个可选择的新方向，而不是只接收一个标准答案；
5. 把选中的方向转化为一个可以立即开始的最小行动。

### 2. 网站如何帮助学生走出“卡住”

网站的核心干预链条为：

**卡住识别 → 任务澄清 → 方法匹配 → 支架提问 → 学生产生新思路 → 学生选择方向 → 形成最小行动 → 记录反馈**

其中，AI 不直接替学生完成任务，而是承担三种角色：

- **诊断辅助者：** 帮助学生描述和区分当前卡点；
- **思维引导者：** 用结构化问题、限制或方法刺激学生产生自己的想法；
- **行动转化者：** 帮助学生把模糊方向转成具体、低门槛的下一步。

### 3. 网站与毕业论文的关系

论文与网站不是两个独立成果，而是一组“理论研究 + 设计实践”：

- 论文梳理创造力、教学脚手架与 AI 辅助学习理论；
- 网站把理论转化为具体情境、交互流程和支架内容；
- 原型测试用于观察学生是否更容易产生思路、明确方向并开始行动；
- 反馈数据支持论文讨论工具的可用性、有效性、自主性与潜在风险；
- 论文最终总结设计原则、应用边界和后续改进方向。

因此，网站是论文研究问题的实践载体，论文是网站功能选择与效果评价的依据。

## 二、论文方向规划

以下题目均为待讨论候选。为控制研究范围，题目暂以“大学生”和“开放性学习任务”为主要假设，后续仍需根据可接触的研究对象和学校要求确认。

### 方向一

**面向大学生开放性学习任务的 AI 创造力支架设计研究：从“卡住”识别到最小行动**

**优点：**

- 与网站完整流程最一致，论文和产品可以共用同一套概念框架；
- 适合采用设计型研究、原型测试、访谈或可用性研究；
- 即使前期不接入真实 AI API，也可以测试支架流程与内容；
- 研究成果可以沉淀为一套较完整的设计原则。

**缺点：**

- “开放性学习任务”仍然偏宽，需要进一步限定任务类型；
- 同时涉及卡住识别、创造力支架和行动转化，论文篇幅可能分散；
- 若缺少清晰评价指标，容易停留在产品说明层面。

### 方向二

**情境匹配型 AI 创造力支架对大学生任务推进的影响研究**

**优点：**

- 聚焦“不同卡点匹配不同支架”这一核心机制；
- 容易形成明确的自变量、过程和结果指标；
- 可以比较匹配支架、通用提示或无支架条件之间的差异。

**缺点：**

- 需要较清楚地定义“匹配”与“任务推进”；
- 较适合实验或准实验设计，对样本、测试流程和数据质量要求更高；
- 若没有足够用户样本，结论可能不稳定。

### 方向三

**答案生成型 AI 与思维支架型 AI 对大学生创意任务表现及学习自主性的比较研究**

**优点：**

- 对比关系清楚，能够突出本项目区别于普通 AI 问答工具的价值；
- 可同时讨论创意表现、任务推进和自主性；
- 研究结果具有较强的教育应用意义。

**缺点：**

- 需要控制两种 AI 条件的输出质量，实验设计难度较高；
- “创意表现”和“自主性”都需要可靠的测量方式；
- 可能需要真实 AI 或高度一致的模拟材料，实施成本较高。

### 方向四

**学生学习任务中的“卡住”情境分类及创造力支架匹配机制研究**

**优点：**

- 直接解决网站最基础的分类与推荐逻辑；
- 可以先通过访谈、问卷、案例分析和文献梳理建立分类框架；
- 不依赖完整网站或真实 AI，前期可行性较高；
- 研究结果可直接指导情境选择页与支架规则设计。

**缺点：**

- 更偏前期模型构建，可能弱化网站整体体验和效果验证；
- 分类结果可能受任务类型和学生群体影响，泛化需要谨慎；
- 需要避免只凭主观经验划分类型。

### 方向五

**AI 创造力支架工具的设计与应用研究：以大学生写作卡顿为例**

**优点：**

- 将用户、任务和场景限定得较具体，研究范围最容易控制；
- 写作卡顿较容易设计任务、观察过程并收集前后结果；
- 网站功能和支架示例更容易落地；
- 适合毕业论文时间有限、样本有限的情况。

**缺点：**

- 网站最初设想中的学习、表达、项目规划等场景会被暂时排除；
- 研究结果未必能直接推广到所有创造性任务；
- 需要进一步区分“创造力卡顿”与一般写作知识不足。

### 初步建议

当前更建议优先比较：

- **方向一：** 适合以网站整体设计和理论转化为主；
- **方向四：** 适合先解决“卡住类型如何分类、如何匹配支架”；
- **方向五：** 适合在时间和样本有限时，用写作场景控制研究范围。

正式确定题目前，需要回答四个收窄问题：

1. 最容易接触的研究对象是哪个学段、年级或专业？
2. 第一版只研究写作，还是包含多种开放性学习任务？
3. 论文更希望产出设计原则，还是验证干预效果？
4. 可以获得多少测试参与者，以及能否进行前后对比或分组测试？

## 三、网站 MVP 功能规划

### MVP 范围原则

MVP 只验证一件事：**结构化创造力支架能否帮助学生从某种卡住状态走到一个可执行的下一步。**

初版暂不包含账号系统、社交功能、教师后台、复杂数据分析、跨设备同步、完整作业生成、后端服务或真实 AI API。

### 1. 首页

**目标：** 让学生快速理解网站用途，并愿意开始一次“脱卡”流程。

**核心内容：**

- 一句话说明：“不是替你完成，而是帮你找到继续思考的下一步”；
- 常见卡住状态的简短示例；
- “开始脱卡”主按钮；
- 简短说明隐私、学术诚信和 AI 使用边界。

**完成标准：** 用户能够在短时间内理解网站不是普通聊天机器人，并知道下一步点击哪里。

### 2. 卡住情境选择

**目标：** 帮助学生识别最接近当前状态的卡点。

**MVP 建议情境：**

- 不知道从哪里开始；
- 想不出更多点子；
- 做到一半无法继续；
- 想法太普通或太相似；
- 任务太大、太模糊；
- 知道要做什么，但迟迟无法行动。

**完成标准：** 用户可以选择一个主要情境；若不确定，可选择“说不清，但我确实卡住了”进入简短辅助判断。

### 3. 任务输入

**目标：** 用尽可能低的输入负担获得支架所需信息。

**MVP 输入项：**

- 我正在做什么；
- 我目前做到哪里；
- 我希望下一步解决什么；
- 可选：限制条件、已有想法或截止时间。

**完成标准：** 必填信息控制在少量字段内，用户不需要先写一篇完整背景说明。

### 4. AI 创造力支架

**目标：** 根据卡住情境提供一种主要方法，引导学生参与思考。

**交互原则：**

- 每次只展示一个小问题或一个小步骤；
- 先让学生作答，再继续提供下一层提示；
- 说明当前正在使用的方法及用途；
- 允许“换一种方法”，但避免一次堆叠过多技巧；
- 不直接输出可提交的完整成品。

**完成标准：** 每个 MVP 卡住情境至少有一套可执行支架流程，且每套流程能引导学生留下自己的输入。

### 5. 新思路生成

**目标：** 让学生把支架过程转化为多个候选方向。

**核心功能：**

- 记录学生产生的思路；
- 支持补充、合并或改写思路；
- 鼓励至少保留三个方向；
- 由学生选择一个最想继续发展的方向。

**完成标准：** 结果页体现“学生生成与选择”，而不是系统直接宣布唯一答案。

### 6. 最小行动步骤

**目标：** 把选定思路转成可以立即开始的行动。

**行动格式建议：**

**动作 + 对象 + 时间或数量限制**

例如：“用 5 分钟写出三个不同开头”“先列出任务的三个子问题”“用一句话说明这个方案最特别的地方”。

**完成标准：** 最终步骤应具体、短小、无需额外准备，原则上可在 5 至 15 分钟内开始或完成。

### 7. 反馈记录

**目标：** 同时支持产品改进和论文研究材料积累。

**MVP 反馈项：**

- 使用前后“卡住程度”自评；
- 是否产生了新的方向；
- 哪种提示最有帮助；
- 最小行动是否清楚；
- 是否愿意现在开始行动；
- 一项简短开放反馈。

**完成标准：** 反馈填写时间短，能够反映卡住缓解、思路产生和行动意愿三个方面。

## 四、理论支撑规划

以下内容是候选理论与方法清单，后续需要通过正式文献检索确认概念定义、适用边界和测量方式，当前不把它们视为已经完成的理论框架。

| 理论或方法 | 在项目中的作用 | 可转化的网站机制 |
|---|---|---|
| 发散思维 | 帮助学生暂缓评价并产生多个不同方向 | 限时列举、不同类别提示、至少三个候选思路 |
| 聚合思维 | 从多个方向中选择并发展更合适的方案 | 比较标准、方向选择、可行性判断 |
| 类比启发 | 从其他对象、领域或经验迁移结构 | “这个问题像什么”以及跨领域类比提示 |
| SCAMPER | 用固定操作维度系统拓展已有想法 | 替代、组合、调整、修改、改变用途、删除、重排提示卡 |
| 反向假设 | 打破默认前提和惯性思路 | “如果目标相反”“如果不能使用常规方法” |
| 视角转换 | 从不同角色、时间或立场重看任务 | 角色卡、受众视角、未来回看 |
| 限制条件创意 | 通过主动缩小范围降低空白压力并刺激想法 | 时间、字数、材料或目标限制 |
| 任务拆解 | 降低任务复杂度，帮助学生找到起点 | 子任务拆分、优先级选择、五分钟行动 |
| 脚手架教学 | 依据学习者当前状态提供适量支持，并逐步减少帮助 | 分步提示、提示层级、先问后提示、学生自主选择 |
| 元认知与自我调节学习 | 帮助学生觉察卡点、选择策略并监控进展 | 卡点自评、策略说明、前后状态反思 |
| AI 辅助学习 | 提供适应性反馈和个性化提示，同时控制依赖风险 | 情境匹配、动态追问、输出边界与学术诚信提醒 |
| 行动启动与最小步骤 | 降低开始行动所需的心理与认知门槛 | 动作化表述、时间限制、立即开始确认 |

### 理论到功能的初步匹配

| 卡住情境 | 优先候选支架 |
|---|---|
| 不知道从哪里开始 | 任务拆解、提问支架、最小行动 |
| 想不出更多点子 | 发散思维、SCAMPER、随机刺激 |
| 做到一半无法继续 | 类比启发、视角转换、递进提问 |
| 想法太普通 | 反向假设、限制条件创意、类比启发 |
| 任务太大或太模糊 | 任务拆解、目标澄清、优先级选择 |
| 知道要做什么但无法行动 | 最小步骤、时间限制、自我调节提示 |

该匹配表目前只是设计假设，后续应由文献、专家意见和用户测试共同修正。

## 五、开发阶段规划

### 阶段 1：确定研究与 MVP 边界

**阶段目标：** 确定研究对象、首要任务场景、卡住定义和论文主要研究问题。

**要完成的文件或页面：**

- 更新 `docs/idea-brief.md` 中的目标用户和优先场景；
- 新增一页研究范围说明；
- 确认一个主论文方向和一个备选方向。

**完成标准：**

- 能用一句话说明“为谁、在什么任务中、解决哪种卡住问题”；
- 明确首版包含和不包含的场景；
- 论文问题与网站核心流程可以相互对应。

**是否需要更新论文材料：** 是。形成研究背景、研究对象、核心概念和初步研究问题。

### 阶段 2：完成理论与需求映射

**阶段目标：** 用文献和用户需求支持卡住分类、创造力方法与评价指标。

**要完成的文件或页面：**

- 理论概念表；
- 卡住情境与支架匹配表；
- 初步用户需求或访谈提纲；
- 评价指标草案。

**完成标准：**

- 每个核心功能都有可追溯的理论或需求依据；
- 每种卡住情境至少匹配一种主要支架；
- 明确哪些指标用于评价思路、行动和体验。

**是否需要更新论文材料：** 是。同步形成文献综述框架和理论框架草案。

### 阶段 3：完成信息架构与支架内容设计

**阶段目标：** 在不写代码的情况下确认完整用户流程和页面内容。

**要完成的文件或页面：**

- 页面清单；
- 用户流程图；
- 首页与各步骤的文案草案；
- 各情境的支架脚本；
- 反馈问题清单。

**完成标准：**

- 用户从首页到最小行动没有流程断点；
- 每一步的输入、输出和跳转条件明确；
- 支架脚本不直接替学生完成任务。

**是否需要更新论文材料：** 是。记录理论如何转化为设计原则和功能。

### 阶段 4：制作低保真原型并进行认知走查

**阶段目标：** 先验证流程是否易懂、负担是否过高。

**要完成的文件或页面：**

- 首页；
- 卡住情境选择页；
- 任务输入页；
- 支架过程页；
- 新思路页；
- 最小行动页；
- 反馈页。

**完成标准：**

- 目标用户能够在少量解释下完成一轮流程；
- 能说清每一步需要做什么；
- 发现并记录主要理解障碍和流程问题。

**是否需要更新论文材料：** 是。记录原型设计过程、走查方法与修改依据。

### 阶段 5：开发静态交互 MVP

**阶段目标：** 在用户明确确认开发方案后，实现可操作的前端原型。

**要完成的文件或页面：**

- 经确认的 React/Vite 项目；
- 七个 MVP 页面或对应步骤组件；
- 本地固定数据与模拟支架流程；
- 基础反馈记录界面。

**完成标准：**

- 核心流程可从头到尾运行；
- 不依赖后端和真实 AI API；
- 页面在目标设备上基本可用；
- 通过相应构建检查。

**是否需要更新论文材料：** 是。记录系统架构、功能实现和设计决策。

### 阶段 6：加入规则匹配或模拟 AI 支架

**阶段目标：** 验证“不同卡点匹配不同支架”的核心机制。

**要完成的文件或页面：**

- 情境到支架的规则表；
- 支架内容数据；
- “换一种方法”路径；
- 输出边界和学术诚信提示。

**完成标准：**

- 相同输入在不同卡住情境下获得不同的支架路径；
- 支架能够促使用户输入和选择；
- 不生成可直接提交的完整作业。

**是否需要更新论文材料：** 是。形成干预机制、变量定义和测试材料。

### 阶段 7：用户测试、分析与迭代

**阶段目标：** 观察工具是否帮助学生产生思路并开始行动。

**要完成的文件或页面：**

- 测试任务与参与说明；
- 同意与隐私说明；
- 前后反馈问卷或访谈提纲；
- 测试记录与问题清单；
- 一轮小范围迭代。

**完成标准：**

- 完成预定人数和场景的测试；
- 能报告卡住程度、思路产生、行动清晰度和使用体验；
- 明确哪些结论有证据支持，哪些仍只是推测。

**是否需要更新论文材料：** 是。同步完成研究方法、结果、讨论、限制与设计建议。

## 六、当前最适合做的下一步

### 下一步任务

**先完成一份“研究与 MVP 范围确认单”，只确定三个变量：目标学生、首要任务场景、主要卡住类型。**

建议用以下句式形成暂定范围：

> 本项目首版面向 ______ 学生，优先支持他们在 ______ 任务中出现的 ______ 卡住状态，并通过 ______ 创造力支架帮助其形成可立即执行的下一步。

### 为什么先做这一步

1. 当前最大的风险不是缺少功能，而是研究对象和任务范围过宽；
2. 论文题目、理论选择、页面文案、支架方法和评价指标都依赖这三个变量；
3. 若先开发综合场景，后续很难设计一致的测试任务和论文研究问题；
4. 这个决定不需要写代码，成本低，却能显著减少后续返工；
5. 完成范围确认后，下一项小任务才适合进入“卡住类型与支架方法匹配表”的正式整理。

### 本阶段暂不做

- 不创建 React/Vite 项目；
- 不安装依赖；
- 不接入后端或真实 AI API；
- 不一次性编写全部支架脚本；
- 不在研究对象未确认前确定最终论文题目；
- 不把网站扩展成通用 AI 聊天工具。
